# Units correction — RSS is MiB, not MB (formatting only)

The harness's byte formatter divided resident-set-size by 1024² (=
1,048,576) but labeled the result "MB". The correct unit for a 1024²
divisor is **MiB** (mebibytes). This is a label-only defect: no byte
value, timing, or rate was ever affected, and the raw byte counts stored
in each run's JSON (`rss_before_bytes`, `rss_peak_bytes`,
`rss_after_bytes`, `rss_mean_bytes`; and `rss_*_index_bytes` in the
retrieval arm summaries) are authoritative and unchanged.

Example: real-153 jobs=1 cold peak = `251871232` bytes
= 251871232 / 1024² = **240.20 MiB** (= 251.87 MB). The formatter
rendered this as "240 MB"; the correct label is "240 MiB".

## What was corrected

- `Tests/VecKitTests/ImageOCRBenchmarkTests.swift` — the formatter now
  prints "MiB" (bytes/timings unchanged), so all FUTURE runs are
  correctly labeled.
- The human-readable summaries generated by earlier runs
  (`*/summary.md`, `*/ocr-throughput.md`) were relabeled "MB" → "MiB"
  in place; only the unit string changed, every number is identical.

## What was deliberately NOT changed

- The verbatim `*/execution-log.txt` launcher logs retain the original
  "MB" label as-run, so the raw historical record is preserved. Any
  "MB" seen in those logs means MiB.

No benchmark was re-run for this correction.
