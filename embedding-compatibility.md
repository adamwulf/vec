# Embedding compatibility: single/batch parity fix

The single/batch embedding fix changes some vectors. Rebuild affected
indexes from their source documents; there is no vector migration.

- **GTE (`gte-base`) and MXBAI (`mxbai-large`):** single-document and query
  embeddings now use the same Float32 attention-mask path as batches.
  Previously, omitting the mask kept inference in Float16 for these
  models' FP16 weights. Existing batch-generated document vectors are
  unchanged. Reindex documents generated by the old `embedDocument`
  path, or rebuild the whole index if its provenance is unknown or mixed.
  Regenerate any cached query embeddings.
- **E5 (`e5-base`):** batches now include `passage: ` within the 2,000
  character cap, matching single-document preprocessing. Documents with
  more than 1,991 trimmed content characters can change when embedded in
  batches (depending on the resulting tokens). Reindex these documents,
  or rebuild the whole E5 index if identifying them is impractical.
  E5 single-document and query vectors are unchanged.
- **BGE and Nomic:** their inference and input conventions are unchanged.

For a complete rebuild, note the existing embedder and chunk settings
with `vec info --db <name>`, then reset and reindex using those settings:

```sh
vec reset --db <name> --force
vec update-index --db <name> --embedder <existing-profile>
```

The reset removes indexed vectors and preserves the source path. Ensure
the source documents remain available. A plain incremental update can
leave unchanged source files' old vectors in place, so it is insufficient
for rebuilding an affected index. Reuse the full profile (including any
custom chunk size and overlap), not just its embedder alias.

See [diagnosis and validation](data/embedding-batch-parity.md) for the
pre-fix measurements and test results. The cosine tolerance remains 0.9999.
